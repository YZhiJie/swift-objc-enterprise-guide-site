第 17 章 播放器与质量指标 ​

播放器是「用户离内容最后 1 米」的地方。同样一条 4Mbps 的流，有人 0.8 秒上屏、有人黑屏 5 秒；同样一次弱网抖动，有人无感、有人卡 3 秒。差别不在「会不会调 AVPlayer」，而在是否把生命周期、缓冲、HLS/DRM、音画同步与指标口径做成一套可观测系统。

17.0 学习目标 ​

完成本章后，你将能够：

  1. 讲清 AVPlayer / AVPlayerItem / AVPlayerLayer 的职责边界与状态迁移，正确处理缓冲、seek 与失败重试；
  2. 解释 HLS 主/媒体播放列表、变体选择与 FairPlay DRM 的最小接入路径，并知道哪些能力只能在真机 + 证书环境验证；
  3. 保证音画同步、后台播放与隔空播放的基本行为，并识别不同步/断播的归因方向；
  4. 给首帧时间、秒开率、卡顿率、播放成功率、端到端延迟、切换次数、VMAF/PSNR 下定义、给公式、定采集口径；
  5. 把播放指标接入第 15 章的发布门禁与灰度实验，并通过「症状 → 假设 → 证伪」路径定位线上质量事故。

// File: PlayerController.swift
import AVFoundation
import UIKit

@MainActor
final class PlayerController {
    let player = AVPlayer()
    private(set) var item: AVPlayerItem?
    private var statusObservation: NSKeyValueObservation?
    private var timeControlObservation: NSKeyValueObservation?

    func load(url: URL) {
        let item = AVPlayerItem(url: url)
        self.item = item
        player.replaceCurrentItem(with: item)

        statusObservation = item.observe(\.status, options: [.initial, .new]) { [weak self] item, _ in
            Task { @MainActor in
                switch item.status {
                case .unknown:
                    break
                case .readyToPlay:
                    self?.player.play()          // ✅ 资源就绪后再播
                case .failed:
                    self?.handleFailure(item.error)   // ❌ 不要在这里无限重试
                @unknown default:
                    break
                }
            }
        }

        timeControlObservation = player.observe(\.timeControlStatus, options: [.new]) { player, _ in
            if player.timeControlStatus == .waitingToPlayAtSpecifiedRate {
                // 记录 waiting reason：evaluatingItem / toMinimizeStalls / noItemToPlay
                _ = player.reasonForWaitingToPlay
            }
        }
    }

    private func handleFailure(_ error: Error?) {
        // 保留错误码与 item.errorLog，再决定换源/降级/提示
    }
}

属性/信号含义怎么用
isPlaybackLikelyToKeepUp系统判断能否持续播不要只信它；与 loadedTimeRanges 一起看
isPlaybackBufferEmpty缓冲耗尽，马上要卡触发降档/等待，而不是继续 play()

automaticallyWaitsToMinimizeStalling自动等待以最小化卡顿默认 true；低延迟场景可设 false，但要自己处理卡顿
  • ⚠️ 坑点：把 preferredForwardBufferDuration = 0 理解为「零缓冲」。0 表示使用系统默认策略，不是立即播放。
  • ✅ 推荐：直播/互动把缓冲目标与抖动缓冲（16.6）联动；点播按网络分档，Wi-Fi 可更激进预加载。
  • ❌ 反例：为了「秒开」把 automaticallyWaitsToMinimizeStalling = false 且不补卡顿兜底，弱网下变成频繁 0.5 秒一卡。

17.2.3 seek：精度、代价与取消 ​

swift
// File: SeekController.swift
import AVFoundation

func seek(_ player: AVPlayer, to seconds: Double, precise: Bool, completion: @escaping (Bool) -> Void) {
    let target = CMTime(seconds: seconds, preferredTimescale: 600)
    let tolerance: CMTime = precise ? .zero : CMTime(seconds: 0.5, preferredTimescale: 600)
    player.seek(to: target, toleranceBefore: tolerance, toleranceAfter: tolerance) { finished in
        completion(finished)
    }
}

func scrub(_ player: AVPlayer, to seconds: Double) {
    player.cancelPendingSeeks()          // ✅ 连续拖动先取消旧 seek，避免排队
    player.seek(to: CMTime(seconds: seconds, preferredTimescale: 600),
                toleranceBefore: .zero, toleranceAfter: .zero)
}

运行方式：Xcode 工程中拖动进度条，对比精确/非精确 seek 的完成时间与画面落点；连续快速拖动时观察旧 seek 是否把新 seek 拖慢。

  • 非精确 seek 允许落在关键帧附近，快但落点可能偏 0.5s；精确 seek 从关键帧解码到目标帧，慢但准确。
  • 直播场景通常只允许「回看已缓冲区间」，不允许 seek 到未缓冲的未来；UI 要先限制可拖动范围。
  • ⚠️ 坑点：每次拖动都发精确 seek 且不取消，主线程被回调淹没，进度条「抖」。
  • ❌ 反例：seek 期间继续接收并渲染旧位置帧，用户看到画面先回跳再前进。

// File: PlaybackErrorHandler.swift
import AVFoundation

enum PlaybackFailure: Equatable {
    case network(statusCode: Int?)
    case drm(code: Int)
    case decode
    case unknown(domain: String, code: Int)
}

func classify(_ error: Error?) -> PlaybackFailure {
    guard let error = error as NSError? else { return .unknown(domain: "nil", code: -1) }
    if error.domain == NSURLErrorDomain {
        return .network(statusCode: (error.userInfo["NSURLErrorFailingURLResponseKey"]
            as? HTTPURLResponse)?.statusCode)
    }
    if error.domain == AVFoundationErrorDomain {
        return .decode
    }
    return .unknown(domain: error.domain, code: error.code)
}

func installObservers(for item: AVPlayerItem, onStall: @escaping () -> Void,
                      onEndError: @escaping (Error?) -> Void) {
    NotificationCenter.default.addObserver(
        forName: AVPlayerItem.playbackStalledNotification, object: item, queue: .main
    ) { _ in onStall() }

    NotificationCenter.default.addObserver(
        forName: AVPlayerItem.failedToPlayToEndTimeNotification, object: item, queue: .main
    ) { note in
        onEndError(note.userInfo?[AVPlayerItemFailedToPlayToEndTimeErrorKey] as? Error)
    }
}

  • ✅ 推荐：低延迟直播用 LL-HLS（EXT-X-PART / EXT-X-PRELOAD-HINT），并确认 CDN 与播放器版本支持；不支持时按普通 HLS 的延迟预算设计。
  • ❌ 反例：把 EXT-X-DISCONTINUITY 前后的时间戳当成连续，音画会跳变；转码/插播必须显式标记不连续。

import AVFoundation

final class FairPlayKeyLoader: NSObject, AVContentKeySessionDelegate {
    private let session = AVContentKeySession.makeContentKeySession()
    private let certificate: Data

    init(asset: AVURLAsset, certificate: Data) {
        self.certificate = certificate
        super.init()
        session.addContentKeyRecipient(asset)
        session.setDelegate(self, queue: .main)
    }

    func contentKeySession(_ session: AVContentKeySession,
                           didProvide keyRequest: AVContentKeyRequest) {
        keyRequest.makeStreamingContentKeyRequestData(
            forApp: certificate,
            contentIdentifier: keyRequest.identifier as? Data,
            options: nil
        ) { [weak self] spc, error in
            guard let self, let spc else {
                keyRequest.processContentKeyResponseError(error ?? NSError(domain: "drm", code: -1))
                return

            // 把 SPC 发给 KSM，拿到 CKC（真实工程必须走后端，不能把密钥放客户端）
            self.requestCKC(spc: spc) { ckc in
                let response = AVContentKeyResponse(fairPlayStreamingKeyResponseData: ckc)
                keyRequest.processContentKeyResponse(response)
            }
        }
    }

        // 生产：HTTPS + 鉴权 + 证书校验 + 重试；离线可 persistableContentKey
    }

17.4 音画同步、后台与隔空播放 ​

17.4.1 音画同步：主时钟与漂移来源 ​

AVPlayer 在同时有音频和视频时，通常以音频为主时钟：视频帧按 presentation timestamp 对齐音频播放位置。同步出问题，先查时间戳而不是先调播放器参数。

症状高概率原因首查
声音超前/滞后固定几十 msAAC priming/编码延迟未补偿、封装时间戳偏移对比音视频首帧 PTS、检查封装/转码链
播放中渐进漂移转码时间基不一致、长 GOP + 丢帧累积看 HLS 分段时间戳、丢帧计数
插播/切台后跳变EXT-X-DISCONTINUITY 处理不当检查 discontinuity sequence 与 PTS
只有视频时不同步无音频主时钟，依赖 host clock用视频 PTS 与渲染时间对比

17.5 质量指标：定义、公式与采集口径 ​

17.5.1 首帧时间与秒开率 ​

首帧时间（Time to First Frame, TTFF）

text
TTFF = t_firstFrameRendered - t_playIntent
1
  • t_playIntent：用户点击播放/自动播放入口触发的时刻（不是页面曝光，也不是 readyToPlay）。
  • t_firstFrameRendered：第一帧真正上屏的时刻。可用 AVPlayerItemVideoOutput 首帧回调 + 渲染完成信号，或用播放器 SDK 的上屏回调；不要用 readyToPlay 代替。
  • 分母：有效播放尝试（用户没有在首帧前主动取消）。取消样本单独计数，不能算失败也不能算成功。

秒开率

text
fastStartRate = count(TTFF ≤ threshold) / count(validPlayAttempts)
1
  • 阈值按业务定义（常见 1s）；必须与看板、告警、门禁使用同一阈值。
  • 聚合用 P50/P90/P95，不能只报平均；平均值会被少量极慢样本拉高。
  • 冷启动/热启动、首次安装/回访要分桶；CDN 命中/回源也要分桶。

17.5.2 卡顿率与单次卡顿时长 ​

先定义「卡顿事件」：播放进入等待且持续超过阈值（例如 200ms），到恢复播放为一对。不要把一次 50ms 的微等待算成卡顿，否则指标噪声淹没信号。

text
stallRatio       = totalStalledMs / totalWatchMs
sessionStallRate = sessionsWithStall / sessions
stallsPer10min   = stallCount / (totalWatchMs / 600000)
avgStallMs       = totalStalledMs / stallCount
1
2
3
4
  • 卡顿率（时长口径） 回答「用户有多少时间在看转圈」；
  • 场次卡顿率 回答「多少用户遇到了卡顿」；
  • 单次卡顿时长 回答「卡一次有多难受」；
  • 每 10 分钟卡顿次数 回答「卡得频不频」。

四个数必须一起看：偶发 8 秒长卡与每 10 分钟 20 次短卡，体验完全不同，治理手段也不同。

  • ⚠️ 坑点：未闭合的卡顿（用户卡到退出）必须计到会话结束，否则最严重的样本被丢掉，卡顿率反而「变好」。
  • ⚠️ 坑点：把 AVPlayerItemPlaybackStalled 通知次数直接当卡顿次数，会漏掉「等待但未触发通知」的样本；要用状态机成对上报。
  • ❌ 反例：只统计「播放中」的卡顿，漏掉起播阶段黑屏等待，秒开与卡顿两套指标互相甩锅。

17.5.3 播放成功率与错误归因 ​

17.5.4 端到端延迟 ​

text
glassToGlassLatency = t_render - t_capture
1
  • 直播链路优先用服务端注入的采集时间戳（NTP/PTP 校准）或端上采集 + 服务端回传校准；未校准的端到端值不要上报。
  • 无法拿到采集时刻时，退而求其次报「播放器缓冲延迟 + 网络段延迟」，但在指标名里写清楚，不要冒充 glass-to-glass。
  • 聚合报 P50/P95；直播互动看 P95，点播不适用此指标。

17.5.5 码率/分辨率切换与 VMAF/PSNR ​

text
switchRate      = switchCount / (watchMs / 60000)      // 次/分钟
oscillationRate = upDownPairsWithin30s / switchCount
1
2
  • 切换要带方向（升/降）与原因（带宽、缓冲、手动选择）；只报总数无法区分「正常适配」与「反复横跳」。
  • presentationSize 变化不等于变体切换；应从 HLS 变体事件或 access log 的码率字段取，字段名随系统版本可能变化，需真机打印确认。

PSNR

text
MSE = (1/N) Σ (I(i) - K(i))²
PSNR(dB) = 10 × log10(MAX² / MSE)
1
2
  • 8bit 像素 MAX = 255；MSE 为 0 时 PSNR 为无穷大，工程上返回 nil/「不可计算」，不要写成 0 或 100。
  • PSNR 对结构/纹理不敏感，适合快速回归，不适合作为唯一画质结论。

VMAF

  • 全参考感知指标，输出 0~100；需要参考片源 + 模型，通常在离线转码/回归环境计算，不在端上实时算。
  • 常用报告：均值 + 1% 分位（最差片段）；不同模型/版本不可直接横比。
  • 端上可用「解码错误率、丢帧率、卡顿率」做代理指标，但不能宣称等于 VMAF。

17.5.7 指标计算的可运行实现 ​

examples/Sources/PlayerMetrics/PlaybackTimeline.swift本地运行：swift run PlayerMetrics
swift
// File: Sources/PlayerMetrics/PlaybackTimeline.swift —— 播放事件时间线与单场分析（17.5）
//
// 设计决策：
//   1. 指标从「事件流」推导，而不是从播放器内部状态采样——事件可上报、可回放、可对账；
//   2. 先定义分母与闭区间：一次 playIntent 到 ended/failed 为一场，未闭合的卡顿计到观测终点；
//   3. success 不只看「有没有出帧」，还要求有效观看时长，避免 0.2 秒闪播污染成功率。

import Foundation

enum PlaybackEventKind: String, Equatable, Sendable {
    case playIntent
    case firstFrame
    case stallBegin
    case stallEnd
    case bitrateSwitch
    case resolutionSwitch
    case ended
    case failed
}

struct PlaybackEvent: Equatable, Sendable {
    var kind: PlaybackEventKind
    var atMs: Double
}

struct PlaybackAnalysis: Equatable, Sendable {
    var firstFrameMs: Double?
    var watchMs: Double = 0
    var stallCount: Int = 0
    var stalledMs: Double = 0
    var stallRatio: Double = 0
    var bitrateSwitches: Int = 0
    var resolutionSwitches: Int = 0
    var success: Bool = false
}

enum PlaybackAnalyzer {

    /// 有效观看下限：低于 3s 的会话不计入播放成功率（口径必须与看板一致）
    static let minimumWatchMs: Double = 3_000

    static func analyze(events: [PlaybackEvent], endMs: Double? = nil) -> PlaybackAnalysis {
        var result = PlaybackAnalysis()
        let ordered = events.sorted { $0.atMs < $1.atMs }
        guard let start = ordered.first(where: { $0.kind == .playIntent }) else { return result }

        let end = endMs ?? ordered.last?.atMs ?? start.atMs
        result.watchMs = max(0, end - start.atMs)
        if let firstFrame = ordered.first(where: { $0.kind == .firstFrame && $0.atMs >= start.atMs }) {
            result.firstFrameMs = firstFrame.atMs - start.atMs
        }

        var stallStartedAt: Double?
        var failed = false
        for event in ordered where event.atMs >= start.atMs {
            switch event.kind {
            case .stallBegin:
                if stallStartedAt == nil {
                    stallStartedAt = event.atMs
                    result.stallCount += 1
                }
            case .stallEnd:
                if let began = stallStartedAt {
                    result.stalledMs += max(0, event.atMs - began)
                    stallStartedAt = nil
                }
            case .bitrateSwitch:
                result.bitrateSwitches += 1
            case .resolutionSwitch:
                result.resolutionSwitches += 1
            case .failed:
                failed = true
            case .playIntent, .firstFrame, .ended:
                break
            }
        }
        // 未闭合的卡顿：计到观测终点，不能当作「没发生」
        if let began = stallStartedAt {
            result.stalledMs += max(0, end - began)
        }
        result.stallRatio = result.watchMs > 0 ? result.stalledMs / result.watchMs : 0
        result.success = result.firstFrameMs != nil && result.watchMs >= minimumWatchMs && !failed
        return result
    }
}

swift
// File: Sources/PlayerMetrics/QualityMetrics.swift —— 播放质量指标的公式实现（17.5）
//
// 设计决策：
//   1. 每个指标一个纯函数，空分母返回 nil——「无数据」与「零」必须能区分；
//   2. 百分位统一 nearest-rank，与第 15 章 MetricKit 的 P90 口径一致；
//   3. PSNR 只作为离线画质回归的粗指标；VMAF 需参考片源与模型，不在端上实时算。

import Foundation

enum QualityMetrics {

    /// nearest-rank 百分位：rank = ceil(p/100 × n)，1-based
    static func percentile(_ values: [Double], _ p: Double) -> Double? {
        guard !values.isEmpty else { return nil }
        let sorted = values.sorted()
        let rank = Int((p / 100 * Double(sorted.count)).rounded(.up))
        return sorted[max(0, min(sorted.count - 1, rank - 1))]
    }

    /// 秒开率 = 首帧 ≤ 阈值 的样本数 / 总播放样本数
    static func fastStartRate(_ firstFrameSamplesMs: [Double], thresholdMs: Double = 1_000) -> Double? {
        guard !firstFrameSamplesMs.isEmpty else { return nil }
        let hits = firstFrameSamplesMs.filter { $0 <= thresholdMs }.count
        return Double(hits) / Double(firstFrameSamplesMs.count)
    }

    /// 卡顿率（时长口径）= 卡顿总时长 / 有效观看总时长
    static func stallRatio(stalledMs: Double, watchMs: Double) -> Double? {
        guard watchMs > 0 else { return nil }
        return max(0, stalledMs) / watchMs
    }

    /// 播放成功率 = 有效成功场次 / 播放尝试场次
    static func playbackSuccessRate(successes: Int, attempts: Int) -> Double? {
        guard attempts > 0 else { return nil }
        return Double(min(max(successes, 0), attempts)) / Double(attempts)
    }

    /// 单次卡顿时长均值（只统计已闭合的卡顿）
    static func averageStallDuration(stallDurationsMs: [Double]) -> Double? {
        guard !stallDurationsMs.isEmpty else { return nil }
        return stallDurationsMs.reduce(0, +) / Double(stallDurationsMs.count)
    }

    /// 每 10 分钟卡顿次数：把「次数」与「时长」分开看，才能区分偶发长卡与高频短卡
    static func stallsPerTenMinutes(stallCount: Int, watchMs: Double) -> Double? {
        guard watchMs > 0 else { return nil }
        return Double(stallCount) / (watchMs / 600_000)
    }

    /// 每分钟码率/分辨率切换次数：振荡的量化指标
    static func switchesPerMinute(switchCount: Int, watchMs: Double) -> Double? {
        guard watchMs > 0 else { return nil }
        return Double(switchCount) / (watchMs / 60_000)
    }

    /// PSNR(dB) = 10 × log10(MAX² / MSE)；MSE 为 0 时理论上无穷大，这里返回 nil（无法用 dB 表达）
    static func psnr(mse: Double, maxValue: Double = 255) -> Double? {
        guard mse > 0 else { return nil }
        return 10 * log10((maxValue * maxValue) / mse)
    }

    /// 逐样本 PSNR：长度不一致或空样本按「不可计算」处理
    static func psnr(original: [Double], reconstructed: [Double], maxValue: Double = 255) -> Double? {
        guard !original.isEmpty, original.count == reconstructed.count else { return nil }
        let mse = zip(original, reconstructed)
            .map { ($0 - $1) * ($0 - $1) }
            .reduce(0, +) / Double(original.count)
        return psnr(mse: mse, maxValue: maxValue)
    }
}

17.6 与发布门禁、灰度实验打通 ​

17.6.1 把播放指标接入第 15 章门禁 ​

第 15 章的 ReleaseGating 用「崩溃率 + 启动 + 核心转化」三指标定生死；播放质量是第四组护栏，组合顺序必须是：

  1. 崩溃/启动（15.6）：一票否决，直接回滚；
  2. 播放成功率：跌破回滚线直接回滚；
  3. 卡顿率 / 首帧 P90：暂停放量（hold），不直接回滚；
  4. Adoption 不足：样本不够，维持小流量，不做结论。
examples/Sources/PlayerMetrics/PlaybackGate.swift本地运行：swift run PlayerMetrics
swift
// File: Sources/PlayerMetrics/PlaybackGate.swift —— 播放质量接入发布门禁（17.6）
//
// 设计决策：
//   1. 与 15.6 的 ReleaseGating 同一方法论：事实结构体进，三档决策 + reason 出；
//   2. 播放指标只作为「额外护栏」，崩溃率仍拥有最高优先级——组合顺序在 17.6 说明；
//   3. 阈值按千万 DAU 的容忍度设定：成功率跌破 98% 回滚，卡顿率超 1.5% 暂停放量。

import Foundation

struct PlaybackFacts: Equatable, Sendable {
    var firstFrameP90Ms: Double       // 首帧 P90
    var stallRatio: Double            // 卡顿时长占比 0...1
    var playbackSuccessRate: Double   // 有效成功 / 尝试
    var adoptionRate: Double          // 当前版本装机占比 0...1
}

enum PlaybackDecision: String, Equatable, Sendable {
    case allow, hold, rollback
}

enum PlaybackGate {

    static let minAdoptionForGate = 0.05
    static let rollbackSuccessRate = 0.98
    static let holdSuccessRate = 0.995
    static let holdStallRatio = 0.015
    static let holdFirstFrameP90Ms: Double = 2_500

    static func decide(_ facts: PlaybackFacts) -> (decision: PlaybackDecision, reason: String) {
        if facts.adoptionRate < minAdoptionForGate {
            return (.hold, "adoption \(facts.adoptionRate) < \(minAdoptionForGate)，维持小流量观察")
        }
        if facts.playbackSuccessRate < rollbackSuccessRate {
            return (.rollback, "播放成功率 \(pct(facts.playbackSuccessRate)) < \(pct(rollbackSuccessRate))，触发回滚线")
        }
        if facts.playbackSuccessRate < holdSuccessRate {
            return (.hold, "播放成功率 \(pct(facts.playbackSuccessRate)) < \(pct(holdSuccessRate))，暂停放量")
        }
        if facts.stallRatio > holdStallRatio {
            return (.hold, "卡顿率 \(pct(facts.stallRatio)) > \(pct(holdStallRatio))，体验劣化")
        }
        if facts.firstFrameP90Ms > holdFirstFrameP90Ms {
            return (.hold, "首帧 P90 \(Int(facts.firstFrameP90Ms))ms > \(Int(holdFirstFrameP90Ms))ms，秒开劣化")
        }
        return (.allow, "全部指标达标")
    }

    private static func pct(_ value: Double) -> String {
        String(format: "%.2f%%", value * 100)
    }
}

17.6.2 灰度实验：主指标与护栏 ​

角色指标说明
主指标播放成功率 / 有效观看时长直接反映「能不能看、愿不愿看」
护栏卡顿率、首帧 P90、崩溃率、切换次数防止主指标变好但体验变差
成本平均码率 / CDN 流量防止「清晰度换成本」不可持续
分桶网络（Wi-Fi/4G/5G）、机型档位、地区、片源避免 Simpson 悖论

  • 样本量：两臂比较、80% 功效的常用近似 n ≈ 16 × p(1-p) / δ²（每臂）。例：p=0.98、要检测 δ=0.5pp，每臂约 1.25 万场；不要用几十个样本下结论。

  • 实验期：覆盖至少一个完整日夜，排除「首日新鲜感」；新版本首日数据单独标记。

  • 不要偷看：固定窗口或使用序贯检验/alpha spending；反复 peek 会抬高假阳性。

  • 归因：指标变差时先看分桶是否均衡（新版本是否更多落在弱网/低端机），再看代码/配置。

  • ✅ 推荐：灰度实验同时记录「播放器版本 + HLS 配置 + ABR 参数」，否则无法解释同一 App 版本内的差异。

  • ⚠️ 坑点：只按用户 ID 分桶，不按「片源/网络」分层，弱网用户恰好集中在实验组时会误判。

  • ❌ 反例：实验组成功率 +0.2pp 就全量，忽略卡顿率 +1pp 的护栏恶化。

17.8 企业级场景分析 ​

场景一：千万 DAU 短视频 Feed ​

目标：把「秒开」与「不卡」做成可运营指标，而不是靠用户投诉。

动作观测结果（示例口径）

场景二：直播低延迟与卡顿的取舍 ​

策略延迟卡顿风险适用
大缓冲 + 普通 HLS高低秀场/带货，体验优先
LL-HLS + 小缓冲中低中赛事/新闻，延迟敏感
WebRTC低取决于弱网治理连麦/互动
  • ⚠️ 坑点：把点播的「大缓冲保不卡」直接搬到直播，延迟会超出业务容忍；直播必须显式定义延迟预算。
  • ✅ 推荐：延迟与卡顿都进看板，按场景设定不同门禁；不要用一个「播放质量分」糊住两类目标。

实践任务 ​

★ 基础

  1. 跑通 PlayerMetrics：解释「正常/卡顿/失败/未闭合卡顿」四类会话的 success 判定，并说明为什么未闭合卡顿的 success 仍可能为 true。
  2. 用 QualityMetrics 计算给定 10 个首帧样本的 P50/P90/P95 与秒开率，比较平均值与分位数的差异。

★★ 进阶

  1. 给 PlaybackAnalyzer 增加「首帧前取消」事件：取消样本不计入成功率分母，但单独上报取消率；补测试。
  2. 设计一份播放质量看板：至少 6 个指标、每个指标写清定义/公式/分母/分桶维度/告警阈值，并接入 15.6 的门禁顺序。

★★★ 挑战

  1. 在 Xcode iOS 工程中实现一个最小播放器：AVPlayerItem 状态监听 + 缓冲三兄弟 + seek + 失败分桶，用真机弱网（Network Link Conditioner）跑 20 次，输出 TTFF/stall/success 的 P50/P90。
  2. 选一条 30 秒片源，构造「关键帧间隔 1s vs 4s」两版 HLS，测量首帧、seek 落点、卡顿率与码率，解释差异并给出上线选择。

小结与自测 ​

  1. AVPlayerItem.status == .readyToPlay 为什么不能当首帧？首帧时间应该从哪个时刻算到哪个时刻？
  2. isPlaybackBufferEmpty 与 isPlaybackLikelyToKeepUp 分别回答什么问题？只看其中一个会漏掉什么？
  3. 精确 seek 与非精确 seek 的代价差异是什么？连续拖动时为什么必须 cancelPendingSeeks？
  4. HLS 的 EXT-X-TARGETDURATION 与分片时长如何影响直播延迟与卡顿？LL-HLS 改变了什么？
  5. 卡顿率、场次卡顿率、单次卡顿时长、每 10 分钟卡顿次数各自回答什么问题？为什么不能只报一个？
  6. 播放成功率的分母是什么？哪些样本应排除、哪些必须计入失败？为什么 adoption 门槛要先于成功率判断？
参考答案
  1. readyToPlay 只表示资源可开始播放，首帧可能还在解码/等关键帧/等 CDN。首帧时间 = 首帧真正上屏时刻 − 用户播放意图时刻；不能用 readyToPlay 代替上屏。
  2. isPlaybackBufferEmpty 回答「现在是否没数据、马上要卡」；isPlaybackLikelyToKeepUp 回答「系统是否认为能持续播」。前者是即时状态，后者是预测；只看一个会漏掉「缓冲还有但预测要卡」或「缓冲空了但很快恢复」。
  3. 非精确 seek 允许落在关键帧附近，少解码、快；精确 seek 要从关键帧解码到目标帧，慢。连续拖动不取消旧 seek，旧请求会排队并让进度条抖动/回跳。
  4. TARGETDURATION 是分片最大时长，决定播放器最少要等多少数据；分片越长，起播/延迟越大但抗抖动更好。LL-HLS 用部分分片（EXT-X-PART）与预加载提示降低延迟，但需要 CDN/播放器支持。
  5. 卡顿率看「时间占比」，场次卡顿率看「多少用户遇到」，单次时长看「一次多难受」，每 10 分钟次数看「多频繁」。长卡与高频短卡治理手段不同，必须分开。
  6. 分母是有效播放尝试场次（排除首帧前主动取消）；<3s 闪播不算成功；失败、超时、DRM 拒绝都必须计入失败。Adoption 太小时样本不足，1 个失败就能让成功率剧烈波动，所以先用样本门槛拦住。

精通判据 ​

能复现

  • 能在真机 + Network Link Conditioner 下复现一次「首帧 > 3s」：记录 playIntent、item ready、首帧上屏三个时刻，并证明瓶颈在 CDN/关键帧/DRM 的哪一段。
  • 能复现一次「卡顿率虚低」：构造用户卡到退出的会话，证明未闭合卡顿未补 end 时指标被低估，修复后指标回升。

能解释

  • 能解释为什么 readyToPlay 不是首帧、为什么 isPlaybackLikelyToKeepUp 不能单独作为缓冲健康的证据。
  • 能解释一次音画不同步：从 AAC priming、转码时间基、EXT-X-DISCONTINUITY、蓝牙路由四条线索中定位到具体一条。

能量化

  • 能给出本章 8 个核心指标的定义、公式、分母、采集点与分桶维度，并用一组真实样本算出 P50/P90/P95。
  • 能算出检测 0.5pp 成功率差异所需的每臂样本量，并说明为什么不能看几十个样本就下结论。

能兜底

  • 能在成功率跌破 98% 时按 15.6 的门禁顺序触发回滚，同时保留卡顿/首帧护栏，避免「回滚后体验仍差」。
  • 能在 DRM 许可失败/404/断网三类错误下给出不同的降级路径（提示、换源、重试、离线内容），而不是统一弹「网络异常」。

本章把「播放器会不会用」推进到「播放质量能不能被定义、被测量、被门禁」。配合第 16 章的链路治理与第 15 章的发布闭环，音视频产品才具备可运营的质量体系。

1. Optional 速查 ​

写法语义评审意见
if let x = opt { }可选绑定，分支内 x 非可选✅ 首选
guard let x = opt else { return }提前返回，后续直接用 x✅ 入口校验首选
opt ?? defaultValuenil 合并，结果非可选✅ 兜底
a?.b?.c ?? 0可选链，任一环节 nil 即短路✅
opt.map { $0 * 2 }有值变换，结果仍可选（Int?）变换返回非可选
opt.flatMap { ... -> Int? }闭包返回可选，避免 Int??变换返回可选
try? f()错误吞成 nil⚠️ 无需区分错误时
opt! / try! / String!强制解包 / 强制 try / 隐式解包❌ 一律打回（Outlet 除外）

func display(profile: Profile?) -> String {
    guard let name = profile?.nickname else { return "匿名用户" } // 组合拳：可选链+guard
    return name

5. 并发决策表 ​

需求用什么关键点
一个异步调用async/awaitawait 是挂起点，让出线程而非阻塞
固定 2~3 个并发async let同时启动，末尾 try await 汇合
动态数量 / 限流 / 提前取消withTaskGroup / withThrowingTaskGroup结构化：父任务等所有子任务结束才返回
共享可变状态（计数/缓存/账户）actor编译器隔离，替代 NSLock
跨并发域传值Sendable（struct 自动；final class 需不可变或加锁）Swift 6 违反即编译错误
UI 相关@MainActor所有 UI 更新必须在 MainActor
GCD/回调旧 API（单值）withCheckedContinuation见第 6 节
多值异步流（进度/通知/字节流）AsyncStream / AsyncSequencefor await 消费；yield 多值、finish 结束；背压用 bufferingNewest(n)，清理用 onTermination

取消 API

API行为
Task.checkCancellation()已取消立即抛 CancellationError（检查点）
Task.isCancelled轮询标记，适合「取消 = 提前返回」
task.cancel() / group.cancelAll()只设标记并沿任务树级联，不强杀
try await Task.sleep(...)内置检查点，取消时立即抛错
withTaskCancellationHandler(onCancel:)把取消翻译成旧 API 动作（移除观察者等）
  • ⚠️ 取消是常态路径：defer 关文件/释放连接；长循环必须有检查点，否则取消形同虚设。
  • ⚠️ actor 在 await 点会重入：禁止「读余额 → await → 写回」，恢复后以隔离区内最新状态为准。
  • ❌ 反例：Task { } 无管理地 fire-and-forget，取消与错误传播全部失效。

详见 2.2 现代并发总览、Actor：用编译器替代锁、Sendable 与严格并发、协作取消、AsyncSequence 与 AsyncStream；可运行 AsyncBasics / CancellationDemo / ActorBank。

6. Continuation 桥接模板 ​

swift
func fetch() async throws -> Data {
    try await withCheckedThrowingContinuation { continuation in
        legacyAPI { data, response, error in
            if let error {                                    // ✅ 每条分支恰好 resume 一次
                continuation.resume(throwing: error)
            } else if let data, let http = response as? HTTPURLResponse,
                      (200..<300).contains(http.statusCode) {
                continuation.resume(returning: data)
            } else {
                continuation.resume(throwing: URLError(.badServerResponse))
            }
        }
    }
}
// 必成功回调：withCheckedContinuation + cont.resume(returning:)

7. @objc 与混编可见性规则 ​

nullability：ObjC → Swift

ObjC 注解Swift 导入风险
NS_ASSUME_NONNULL_BEGIN 区间默认String实际为 nil 时运行时崩溃
nullableString?✅ 安全
无注解String! 隐式解包❌ 最危险

@objc 规则

  • 只有继承 NSObject、成员可被 ObjC 表达（桥接类型，无 Swift-only 泛型/struct/enum）才能暴露；
  • @objcMembers 批量暴露；@objc dynamic 打开消息派发（KVO/swizzle 必需）；
  • NS_SWIFT_NAME(foo(bar:)) 定制 Swift 名；+sharedXxx 单例方法自动导入为 .shared；
  • ObjC 调 Swift：.m 中 #import "模块名-Swift.h"（Xcode 自动生成）；Swift 调 ObjC：Bridging Header。

SPM vs Xcode 互操作边界

方向SPM 命令行包Xcode App 工程
Swift → ObjC✅ clang target + import Module（本仓 InteropDemo）✅ Bridging Header
ObjC → Swift❌ clang target 不能依赖 Swift target✅ 模块-Swift.h
iOS UI / 桥接头❌ 需 Xcode 工程✅

详见 4.3 ObjC 调 Swift、4.4 Swift 调 ObjC、4.5 nullability、4.6 动态特性场景、3.3 消息转发。

阶段UIKitSwiftUI
首次就绪（一次）viewDidLoad：建视图、拉数据.task { await load() }（销毁自动取消）

App 前后台SceneDelegate@Environment(\.scenePhase) + .onChange

  • ⚠️ .onAppear 可多次触发，一次性请求用 .task，任务随视图身份自动取消。

扩展触点硬约束 ​

触点硬约束评审红线
App 扩展（通用）独立进程、内存受限、无共享内存逻辑放共享 framework/包，扩展壳只做展示
App Group 共享UserDefaults(suiteName:) 只保数据，无跨进程通知数据变更用 Darwin 通知「敲门」（CFNotificationCenter）
Widget 刷新系统按预算给刷新机会，时间线是预渲染快照刷新策略决策化：rare→never > 预算见底→atEnd > 业务节拍→after
App Intents进程内直调 perform()（iOS 16+）openAppWhenRun = false 做无感快捷指令；实体查询确定性排序
通知 Service Extensionmutable-content: 1 触发，contentHandler 秒级时限超时系统投递原始 payload——解密失败必须脱敏降级
Share 扩展禁用后台 URLSession上传排队交主 App（后台任务）完成

场景正确做法错误做法

核心心智模型：每个异步任务都属于一棵任务树（Task Tree），父任务不会在所有子任务完成前返回；跨并发域传递的数据必须满足 Sendable。

async/await 基础 ​

swift
// File: AsyncBasics.swift
import Foundation

struct User: Codable, Sendable { let id: Int; let name: String }

enum APIError: Error { case badStatus }

func fetchUser(id: Int) async throws -> User {
    let url = URL(string: "https://jsonplaceholder.typicode.com/users/\(id)")!
    let (data, response) = try await URLSession.shared.data(from: url)  // 挂起而非阻塞
    guard (response as? HTTPURLResponse)?.statusCode == 200 else { throw APIError.badStatus }
    return try JSONDecoder().decode(User.self, from: data)
}

// ⚠️ 脚本模式直接使用顶层 await；不要包 Task { }：脚本不会等待分离任务，含挂起点（网络请求）时会无输出退出
do {
    let user = try await fetchUser(id: 1)
    print("用户：\(user.name)")
} catch {
    print("请求失败：\(error)")
}

并行：async let 与 TaskGroup ​

swift
// File: StructuredConcurrency.swift
import Foundation

func load(_ name: String, delay: UInt64) async throws -> String {
    try await Task.sleep(nanoseconds: delay)
    return name
}

func loadDashboard() async throws -> (String, String) {
    // async let：并发绑定，语法最轻；两个任务同时启动
    async let banner = load("banner", delay: 300_000_000)
    async let feed = load("feed", delay: 500_000_000)
    return try await (banner, feed)   // 在此汇合（join）
}

// TaskGroup：任务数量动态时使用
func loadAll(ids: [Int]) async throws -> [String] {
    try await withThrowingTaskGroup(of: String.self) { group in
        for id in ids {
            group.addTask {           // 子任务随父任务取消而取消
                try await load("item-\(id)", delay: UInt64(id) * 100_000_000)
            }
        }
        var results: [String] = []
        for try await item in group { // 按完成顺序收集
            results.append(item)
        }
        return results
    }                                 // 函数返回前所有子任务必然结束 —— 结构化
}

Actor：用编译器替代锁 ​

swift
// File: ActorDemo.swift
actor CacheStore<Key: Hashable & Sendable, Value: Sendable> {
    private var storage: [Key: Value] = [:]

    func value(for key: Key) -> Value? { storage[key] }        // 隔离方法

    func set(_ value: Value, for key: Key) {                   // 隔离方法
        storage[key] = value
    }
}

let cache = CacheStore<String, Int>()

// 脚本模式直接顶层 await（不要包 Task { }，否则进程可能在 await 恢复前退出）
await cache.set(42, for: "answer")     // 跨 Actor 调用必须 await
let v = await cache.value(for: "answer")
print(v ?? -1)

Sendable 与 Swift 6 严格并发检查 ​

Swift 6 语言模式（SWIFT_VERSION = 6.0）下，跨并发域传递非 Sendable 数据是编译错误而非警告。

swift
// File: SendableDemo.swift
// struct 且成员全部 Sendable → 自动满足
struct Report: Sendable {
    let title: String
    let rows: [String]
}

// final class + 不可变成员 → 可声明 Sendable
final class Config: Sendable {
    let env: String
    init(env: String) { self.env = env }
}

// ❌ 可变 class 默认非 Sendable；确需共享时用 Actor 包装或加锁后 @unchecked Sendable（需注释说明理由）
final class LegacyCounter: @unchecked Sendable {
    private var _count = 0
    private let lock = NSLock()
    var count: Int {
        lock.lock(); defer { lock.unlock() }
        return _count
    }
}

some 与 any：两个方向相反的「类型擦除」 ​

写法名称底层适用
some View不透明类型（Opaque Type）编译期确定的单一具体类型返回类型：隐藏实现但保留类型信息
any Storable存在类型（Existential）运行期装箱，动态派发存储/参数：异构集合、依赖注入
swift
// File: SomeAny.swift
protocol Shape { func area() -> Double }
struct Circle: Shape { let r: Double; func area() -> Double { 3.14 * r * r } }
struct Square: Shape { let s: Double; func area() -> Double { s * s } }

// some：调用方不知道具体类型，但编译器知道 —— 零开销
func makeDefaultShape() -> some Shape { Circle(r: 1) }

// any：可以放不同具体类型 —— 有装箱开销
let shapes: [any Shape] = [Circle(r: 1), Square(s: 2)]
print(shapes.map { $0.area() })

2.4 属性包装器（Property Wrapper） ​

把「存取逻辑」从属性中抽离复用。

swift
// File: PropertyWrappers.swift
import Foundation

@propertyWrapper
struct Clamped<Value: Comparable> {
    private var value: Value
    private let range: ClosedRange<Value>

    init(wrappedValue: Value, _ range: ClosedRange<Value>) {
        self.range = range
        self.value = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }

    var wrappedValue: Value {
        get { value }
        set { value = min(max(newValue, range.lowerBound), range.upperBound) }  // 写时钳制
    }
}

struct Player {
    @Clamped(0...100) var hp: Int = 100
}

var p = Player()
p.hp = 150
print(p.hp)   // 100

2.5 Result Builder：@ViewBuilder 的原理 ​

Result Builder 把「一串表达式」转换为「一个组合值」，是 SwiftUI 声明式语法的编译期魔法。

swift
// File: ResultBuilder.swift
@resultBuilder
struct HTMLBuilder {
    static func buildBlock(_ parts: String...) -> String {   // 合并多个表达式
        parts.joined(separator: "\n")
    }
    static func buildOptional(_ part: String?) -> String {   // 支持 if
        part ?? ""
    }
    static func buildEither(first: String) -> String { first }  // 支持 if-else
    static func buildEither(second: String) -> String { second }
    static func buildArray(_ parts: [String]) -> String {    // 支持 for
        parts.joined(separator: "\n")
    }
}

@HTMLBuilder
func page(showFooter: Bool, items: [String]) -> String {
    "<html>"
    "<body>"
    for item in items {
        "<li>\(item)</li>"
    }
    if showFooter {
        "<footer>end</footer>"
    }
    "</body>"
    "</html>"
}

print(page(showFooter: true, items: ["a", "b"]))

三件套：weak / unowned / 捕获列表 ​

swift
// File: ARCDemo.swift
class DataLoader {
    var onFinish: (() -> Void)?
    private var cache: [String] = []

    func start() {
        // ❌ 反例：闭包强引用 self，self 又持有闭包 → 循环引用
        // onFinish = { self.cache = ["done"] }

        // ✅ 修复：捕获列表声明弱引用
        onFinish = { [weak self] in
            self?.cache = ["done"]
        }
    }
    deinit { print("DataLoader 释放") }
}

class Owner {
    // weak：对象释放后自动变 nil（必须 Optional）
    weak var delegate: AnyObject?
    // unowned：假定生命周期 ≥ 持有者，释放后访问崩溃（非 Optional）
    unowned let parent: DataLoader
    init(parent: DataLoader) { self.parent = parent }
}

2.8 任务取消与回调桥接 ​

协作取消（Cooperative Cancellation） ​

Swift 并发的取消是协作式的：Task.cancel() / cancelAll() 只设置 isCancelled 标记（发信号），不会从外部强杀任务。任务必须在内部主动响应，停止时机由任务自己掌握——这避免了「线程强杀无法保证资源释放」的问题。

swift
// File: CancellationPatterns.swift
import Foundation

func responsiveWork() async throws {
    for _ in 0..<100 {
        try Task.checkCancellation()       // ① 显式检查点：已取消则抛 CancellationError
        try await Task.sleep(nanoseconds: 10_000_000)  // ② sleep 本身在取消时立即抛错
    }
    if Task.isCancelled {                  // ③ 轮询标记：适合「取消 = 提前返回」而非抛错
        return
    }
}

withTaskCancellationHandler 把基于回调 / NotificationCenter 的旧 API 接入协作取消：取消信号到达时执行 onCancel 闭包，翻译成旧 API 自己的取消动作。

swift
// File: LegacyCancellation.swift
import Foundation

func waitForNotification(_ name: Notification.Name) async {
    // Swift 6：observer token 会在通知闭包与 onCancel 闭包间共享，用锁盒保证互斥
    final class TokenBox: @unchecked Sendable {
        let lock = NSLock()
        var token: NSObjectProtocol?
    }
    let box = TokenBox()
    await withTaskCancellationHandler {
        await withCheckedContinuation { (continuation: CheckedContinuation<Void, Never>) in
            box.token = NotificationCenter.default.addObserver(
                forName: name, object: nil, queue: nil) { _ in
                box.lock.lock(); let token = box.token; box.token = nil; box.lock.unlock()
                if let token { NotificationCenter.default.removeObserver(token) }  // 先摘监听
                continuation.resume()       // 再恢复；通知重复到达时 token 已为 nil，保证只 resume 一次
            }
        }
    } onCancel: {
        box.lock.lock(); let token = box.token; box.token = nil; box.lock.unlock()
        if let token { NotificationCenter.default.removeObserver(token) }  // ✅ 取消即拆除旧订阅
    }
}

swift
// File: CancellationDemo.swift
import Foundation

// 子任务：每步 sleep 100ms，共 10 步（约 1 秒）；在循环中主动响应取消
func worker(id: Int) async throws -> String {
    for step in 1...10 {
        try Task.checkCancellation()                          // ① 显式检查点
        try await Task.sleep(nanoseconds: 100_000_000)        // ② sleep 也响应取消
        print("子任务 \(id) 完成第 \(step) 步")
    }
    return "任务 \(id) 正常完成"
}

// 父任务：用 ThrowingTaskGroup 启动 5 个并发子任务
let parent = Task {
    try await withThrowingTaskGroup(of: String.self) { group in
        for id in 1...5 {
            group.addTask {
                do {
                    let msg = try await worker(id: id)
                    return "存活：\(msg)"
                } catch is CancellationError {
                    return "被取消：任务 \(id)"                 // ✅ 区分取消与业务错误
                }
            }
        }
        var alive = 0
        var cancelled = 0
        for try await result in group {                       // 按完成顺序收集
            print(result)
            if result.hasPrefix("存活") { alive += 1 } else { cancelled += 1 }
        }
        print("统计：存活 \(alive) 个，被取消 \(cancelled) 个")
    }
}

回调到 async 的桥接 ​

用 withCheckedThrowingContinuation（可失败）/ withCheckedContinuation（必成功）把 completionHandler 风格旧 API 封装为 async：

swift
// File: ContinuationBridge.swift
import Foundation

// 封装 iOS 15 之前的 URLSession completionHandler 旧 API
func fetchData(url: URL) async throws -> Data {
    try await withCheckedThrowingContinuation { continuation in
        URLSession.shared.dataTask(with: url) { data, response, error in
            // ✅ 覆盖所有分支，且每条分支恰好 resume 一次
            if let error {
                continuation.resume(throwing: error)
            } else if let data,
                      let http = response as? HTTPURLResponse,
                      (200..<300).contains(http.statusCode) {
                continuation.resume(returning: data)
            } else {
                continuation.resume(throwing: URLError(.badServerResponse))
            }
        }.resume()
    }
}

// 自定义回调（不会失败）→ withCheckedContinuation
func legacyGetValue(completion: @escaping @Sendable (Int) -> Void) {
    DispatchQueue.global().asyncAfter(deadline: .now() + 0.01) { completion(42) }
}

func getValue() async -> Int {
    await withCheckedContinuation { continuation in
        legacyGetValue { continuation.resume(returning: $0) }
    }
}

  • withUnsafeThrowingContinuation 省略全部运行时检查，仅限极端性能敏感、且已用 Checked 版本充分验证后使用，普通桥接一律用 Checked 版本。

AsyncSequence 与 AsyncStream：多值异步序列 ​

withCheckedContinuation 只能桥接「一次性」结果；进度、通知、流式数据这类多次产出的异步源，用 AsyncSequence——它是异步版 Sequence，用 for await ... in 消费，元素随到随取，序列结束或抛错时循环退出。

系统 API 已大量 AsyncSequence 化（一行示例）：

swift
// File: AsyncSequenceSystemAPI.swift
import Foundation

// 通知中心：每条通知成为序列的一个元素
let notes = NotificationCenter.default.notifications(named: Notification.Name("DownloadDidStart"))
// URLSession 字节流：边收边读，不必等整个 body 下载完
let (bytes, _) = try await URLSession.shared.bytes(from: URL(string: "https://example.com")!)
for try await line in bytes.lines { print(line) }       // 按行迭代响应体
// 文件句柄：管道/标准输入流式读取
let lines = FileHandle.standardInput.bytes.lines

回调式 API 没有现成 AsyncSequence 时，用 AsyncStream 主动桥接——它就是「多值版 continuation」：

swift
// File: AsyncStreamDemo.swift
import Foundation

// 传统回调式「下载进度」API：进度回调多次（0.3/0.7/1.0）+ 完成回调一次
final class LegacyDownloader {
    func download(onProgress: @escaping @Sendable (Double) -> Void,   // Swift 6：跨并发域回调必须 @Sendable
                  onComplete: @escaping @Sendable () -> Void) {
        let steps: [Double] = [0.3, 0.7, 1.0]
        for (i, progress) in steps.enumerated() {
            DispatchQueue.main.asyncAfter(deadline: .now() + Double(i + 1) * 0.2) {
                onProgress(progress)
                if progress >= 1.0 { onComplete() }   // 最后一次进度后回调完成
            }
        }
    }
}

// 桥接为 AsyncStream<Double>：Continuation 的多值版，yield 一个元素、finish 结束序列
func downloadProgress() -> AsyncStream<Double> {
    AsyncStream(bufferingPolicy: .bufferingNewest(2)) { continuation in
        let downloader = LegacyDownloader()
        downloader.download(
            onProgress: { continuation.yield($0) },   // 每次进度 → 序列的一个元素
            onComplete: { continuation.finish() }     // 完成 → 结束序列（for await 退出）
        )
        continuation.onTermination = { @Sendable _ in
            // 消费者 break / Task 取消时回调：在此取消底层下载、移除观察者等资源清理
            // downloader.cancel()
        }
    }
}

// for await 消费：天然支持多值，序列 finish 后循环正常结束
for await progress in downloadProgress() {
    print(String(format: "进度：%.0f%%", progress * 100))
}
print("下载完成")

bufferingPolicy 背压策略（生产者比消费者快时如何取舍）：

策略行为适用
.unbounded全部缓存不丢值（内存可能无限增长）值必须全保且产量有界（如迁移进度）
.bufferingNewest(n)只留最新 n 个，丢弃旧值进度条/状态表（只关心最新值）✅ 最常用
.bufferingOldest(n)只留最旧 n 个，丢弃新值日志/事件顺序消费，不许跳过历史
  • ✅ 资源清理由 onTermination 承担：消费者 break、Task 取消或序列释放时回调，在这里取消底层下载、移除观察者、关闭句柄——与单值 continuation「resume 后释放」的职责对应。
  • ✅ 选型口诀：单值（一次请求/一次授权结果）→ withCheckedContinuation；多值（进度/通知/字节流）→ AsyncStream；系统已提供 AsyncSequence 的 API（bytes、notifications、lines）直接消费，不要重复包装。
  • ⚠️ yield 永不阻塞生产者，背压只能靠 buffer 策略取舍——生产者持续远快于消费者时 .unbounded 会吃光内存；消费侧 Task 被取消时迭代自动停止并触发 onTermination。

企业级场景分析 ​

场景：百万级 DAU App 的并发治理 ​

某内容 App 在 Swift 5 模式下累积了 3000+ 并发警告，升级到 Xcode 16 后强制治理，经验如下：

  1. 分层治理：网络层、存储层先 Actor 化（边界清晰、收益最大）；UI 层全量 @MainActor；中间的业务 Service 按依赖关系逐个迁移。
  2. 典型踩坑：一个「全局配置单例」被 200 处引用，直接加锁报大量 Sendable 警告。最终方案：配置改为 struct Config: Sendable，通过 Actor 容器热更新，读取方拿值类型快照——既过检查又消除锁竞争。
  3. 灰度策略：CI 对「新增并发警告」计数门禁，只允许下降不允许上升；两个版本周期内警告清零，随后全工程切 Swift 6 模式。
  4. 收益：上线后崩溃率中「并发野指针/数组越界」类下降约 40%，这类崩溃此前无法通过 code review 稳定拦截。

场景：循环引用的系统性排查 ​

企业工程推荐「工具 + 规范」双管齐下：

  • 规范：所有闭包回调默认 [weak self]，Review 清单固定项（见第 9 章）。
  • 工具：Memory Graph（第 6 章）定期巡检核心链路；单元测试中用 weak 引用断言释放（第 7 章）。

小结与自测 ​

要点回顾

  • 结构化并发：任务成树、父等子、可级联取消；固定并发用 async let，动态用 TaskGroup。
  • Actor + Sendable 是 Swift 6 并发安全的两大支柱；迁移靠「先警告、分模块、门禁防回退」。
  • some 编译期确定零开销，any 运行期装箱更灵活。
  • 属性包装器封装横切逻辑；Result Builder 是 SwiftUI DSL 的原理。
  • 循环引用三件套：weak（默认）、unowned（生命周期可证）、捕获列表（闭包）。

自测题

  1. TaskGroup 相比手动创建多个 Task 有何结构性优势？
  2. 为什么 Actor 的方法之间仍可能出现数据不一致（重入问题）？如何避免？
  3. @unchecked Sendable 意味着什么？使用时必须满足什么前提？
  4. some Shape 与 any Shape 作为返回类型时有何本质区别？
  5. weak 与 unowned 在对象释放后的行为差异是什么？
参考答案
  1. TaskGroup 的子任务随父任务统一取消、统一等待，异常会沿结构化路径传播；手动 Task 是「非结构化」的，生命周期需自行管理，容易泄漏与丢取消。
  2. Actor 方法内的 await 挂起点会让出执行权，其他任务可进入 Actor 修改状态（重入）。避免方式：await 前完成状态校验、await 后重新读取状态、或将不变量逻辑拆为非隔离纯函数。
  3. 表示「编译器请跳过检查，我（开发者）保证线程安全」。前提：内部用锁/队列等机制真正保护了所有可变状态，并在注释中写明理由，否则等于埋下数据竞争。
  4. some Shape 返回的是一个编译期固定但隐藏的具体类型（如总是 Circle），零装箱开销；any Shape 返回的是存在类型装箱，可承载任意 Shape 实现，有动态派发开销。
  5. weak 引用在对象释放后自动置 nil（安全访问得到 nil）；unowned 不会置 nil，释放后访问直接崩溃——仅当能证明被引用对象生命周期不短于持有者时使用。

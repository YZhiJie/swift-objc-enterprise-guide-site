## 格1 · 开播 5 秒黑屏

- **格号**：1
- **画面构图**：直播间后台。斯威芙蒂坐在监视器前，手机预览窗一片黑，只剩转圈；右侧在线人数从 `1200` 跌到 `300`，弹幕气泡不断弹出「卡了」「主播跑路？」。墙上服务端大盘是绿色，形成「机房说没事、用户说没法看」的对峙。
- **角色动作与表情**：斯威芙蒂一手拍桌、一手举着手机给长老看，眉毛拧成问号；长老站在身后，眼镜反出链路的光，表情冷静。
- **旁白**：开播第 5 秒，画面还是黑的。服务端监控全绿，用户却已经用脚投票。
- **对白**：
  - 斯威芙蒂：「服务端全绿，CDN 也没报警，那是谁在黑我的屏？」
  - Runtime 长老：「绿的是机房，不是链路。你连卡在哪一跳都还没证据。」
- **屏幕字幕或关键标注**：`开播 5s：黑屏`；`在线 1200 → 300`；`服务端：正常`；`用户：卡`。

## 格2 · 七跳链路，先给每一跳打点

- **格号**：2
- **画面构图**：白板横贯画面，画着七节链环：采集 → 前处理 → 编码 → 封装 → 传输 → 分发 → 播放。每节链环上方挂一个小 signpost 旗；传输一节闪红。右侧贴着三张协议卡：RTMP、SRT、WebRTC。斯威芙蒂拿马克笔站在「传输」前，长老用教鞭点着「播放」。
- **角色动作与表情**：斯威芙蒂从抓头变成认真标注；长老抬手指向链尾，示意「端到端」而不是「单点」。
- **旁白**：卡顿不是一格血条，而是一条七节链路。每一跳都要有同名的 stage 和可观测点，故障才不会被踢皮球。
- **对白**：
  - 斯威芙蒂：「七跳里到底哪一跳在偷时间？」
  - Runtime 长老：「先给 capture、encode、send、play 打同一口径的 signpost，再谈优化。」
- **屏幕字幕或关键标注**：七跳名称；`capture / preprocess / encode / mux / send / decode / render`；`采集：FPS/丢帧`；`编码：耗时/码率/GOP`；`传输：缓冲/RTT/丢包/重连`；`播放：首帧/卡顿/切换`；协议卡 `RTMP 2~10s`、`SRT 200ms~2s`、`WebRTC 100~400ms`。
- **需在 SVG 中体现的关键元素**：七个链环节点与箭头；每节点上方小旗（signpost）；「传输」节点红色脉冲；四枚指标徽章；三张协议卡及延迟数字；一条从采集到上屏的虚线时间轴。

## 格3 · 弱网三件套：先保连续，再谈清晰

- **格号**：3
- **画面构图**：运维台变成三个并排的小装置：左边码率阶梯（4M → 2.5M → 1.8M → 1.2M），中间 FEC 冗余包与 NACK 回执，右边抖动缓冲水箱。斯威芙蒂把码率旋钮往左拧，长老盯着缓冲水位，屏幕角落显示丢包 `8%`、缓冲 `300ms`。
- **角色动作与表情**：斯威芙蒂动作果断但紧张；长老按住她另一只手，示意「安全降档可以越过冷却，升档要四条全满足」。
- **旁白**：弱网治理不是把码率一降到底，而是按证据降、按条件升，把连续性和延迟放在同一张账上。
- **对白**：
  - 斯威芙蒂：「丢包 8%，缓冲只剩 300ms，先补包还是先降档？」
  - Runtime 长老：「先保连续：安全降档；关键帧 FEC，普通帧 NACK 最多 2 次；缓冲深度按 P95 抖动算。」
- **屏幕字幕或关键标注**：`丢包 ≥8% 且缓冲 <1.5s → 安全降档（吞吐×0.8）`；`缓冲 <300ms → 无条件降一档`；`冷却 3s`；`升档：缓冲 ≥2s、吞吐 ≥1.4×、丢包 <2%、RTT <200ms`；`depth = max(minDepth, P95×2 + 20~50ms)`；`minDepth ≥60ms`；`P95 60ms → 150ms`；`FEC 20%`；`NACK 2 次 / 200ms`。
- **需在 SVG 中体现的关键元素**：四级码率阶梯与向下箭头；FEC 冗余包（多出 20%）；NACK 信封与「×2」；抖动缓冲水箱与 150ms 刻度；四条升档条件的绿色勾选框；放大的 `8%` 丢包与 `300ms` 水位。

## 讲解页要点（对应正文小节）

1. **16.2 端到端链路与可观测点**：七跳职责边界与每跳指标；signpost 区间名全链路统一，Release 也要保留关键区间。
2. **16.4 编码与 GOP**：码率控制不是越高越好；GOP 过长会拖慢首帧，开播场景可把 GOP 缩到 2s 并主动请求关键帧。
3. **16.5 传输选型**：RTMP 适合上行到 CDN，SRT 抗弱网，WebRTC 用于 100~400ms 的互动；用 TCP 传媒体帧会把丢包变成延迟。
4. **16.6 弱网治理**：FEC/NACK 分级重传、ABR「先安全降、再谨慎升」、抖动缓冲深度公式；切换次数本身也是质量指标。
5. **16.7 企业场景**：开播 30 秒流失率是核心指标；首帧黑屏要同时查关键帧、CDN TTFB 与客户端起播逻辑。

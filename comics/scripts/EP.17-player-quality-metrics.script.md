## 登场角色

- **斯威芙蒂**：播放器开发，负责这次播放内核升级的灰度。看板上全是绿色，客服群里全是「卡成 PPT」。
- **Runtime 长老**：不跟她争「卡不卡」，只让她先把口径、分母和分桶摆到桌上。

## 格1 · 看板全绿，用户全喊卡

- **格号**：1
- **画面构图**：线上作战室。墙上的大看板一片绿色：`平均首帧 0.9s`、`卡顿率 0.2%`、`成功率 98.4%`。桌上手机却在转圈，屏幕写着「卡成 PPT」；空中飘着客服工单气泡。斯威芙蒂举着放大镜，看板背后露出一条又长又红的「P90 尾巴」。
- **角色动作与表情**：斯威芙蒂困惑又委屈，手指着看板问「到底谁在说谎」；长老抱臂站在旁边，表情像在等她先承认「平均值会骗人」。
- **旁白**：所有人都说卡，看板却一切正常。不是数据坏了，是数据被平均得太平滑。
- **对白**：
  - 斯威芙蒂：「平均首帧 0.9 秒，卡顿率 0.2%，用户为什么还说卡成 PPT？」
  - Runtime 长老：「平均值只负责好看。P90 和分母才负责说真话。」
- **屏幕字幕或关键标注**：`平均 TTFF 0.9s`；`卡顿率 0.2%`；`成功率 98.4%`；`P90 TTFF 3.5s`（被看板挡住）；`秒开率 50%`；`工单：卡顿/黑屏/音画不同步`。
- **需在 SVG 中体现的关键元素**：绿色看板与三个大数字；被遮挡的红色 P90 尾巴；旋转加载的手机；客服工单气泡；斯威芙蒂的放大镜；长老抱臂姿态。

## 格2 · 把「卡」翻译成公式

- **格号**：2
- **画面构图**：指标实验室。中央一块大秒表，从「播放意图」走到「第一帧上屏」；下方两张成对的卡顿票根：`stall begin` 与 `stall end`；右侧漏斗写着「播放尝试 → 有效会话 → 成功」。长老用粉笔在玻璃墙上写公式，斯威芙蒂逐项对照埋点。
- **角色动作与表情**：斯威芙蒂从委屈转为专注，拿着本子逐条抄分母；长老写到 `readyToPlay` 时画了一个大红叉。
- **旁白**：指标不是感受，是可复核的口径：起点、终点、分母、分桶，缺一个都能把事故洗成「正常」。
- **对白**：
  - 斯威芙蒂：「TTFF 到底从哪算到哪？」
  - Runtime 长老：「从点击播放，到第一帧真正上屏；`readyToPlay` 不算，取消样本也不能算失败。」
- **屏幕字幕或关键标注**：`TTFF = t_firstFrameRendered − t_playIntent`；`fastStartRate = TTFF≤1s / 有效播放尝试`；`stallRatio = totalStalledMs / totalWatchMs`；`卡顿事件：等待 >200ms 才成对记账`；`success = 首帧 && watch ≥3000ms && 无致命错误`；`successRate = successfulSessions / playAttempts`；`glassToGlass = t_render − t_capture（未校准不上报）`；脚注 `PSNR = 10·log10(MAX²/MSE)`、`VMAF 仅离线回归`。
- **需在 SVG 中体现的关键元素**：大秒表与播放意图/首帧两个时间点；成对的 stall 票根；播放尝试漏斗与分母；公式玻璃墙；`readyToPlay` 红叉；3000ms 有效观看刻度；PSNR/VMAF 小标签放在离线区。

## 格3 · 口径对齐后，门禁才敢说回滚

- **格号**：3
- **画面构图**：发布控制台。一条灰度滑杆从 `5%` 指向 `10%`，旁边是三色门禁灯：崩溃率一票否决、成功率回滚线、卡顿/首帧 hold 护栏、Adoption 样本门槛。斯威芙蒂的手停在拉杆上，长老把一张「97.5% → 回滚」的判定卡拍在桌上。
- **角色动作与表情**：斯威芙蒂先是松一口气，看到成功率跌破回滚线后立刻拉下刹车；长老点头，表情「这才叫按事实办事」。
- **旁白**：门禁不是给发布添堵，是把「用户替我们试错」改成「数据替我们决策」。
- **对白**：
  - 斯威芙蒂：「成功率 97.5%，卡顿 2.1%，卡顿只超了一点，先放量到 10% 行不行？」
  - Runtime 长老：「成功率破 98% 是回滚线，直接回；卡顿超 1.5% 只是 hold。别把两种动作混成一种。」
- **屏幕字幕或关键标注**：`Crash-free <99.5% → 回滚`；`成功率 <98% → 回滚`；`成功率 <99.5% → hold`；`卡顿率 >1.5% → hold`；`首帧 P90 >2.5s → hold`；`Adoption <5% → hold`；`97.5% → rollback`；`2.1% / P90 3.5s → hold`；`样本：p=0.98、δ=0.5pp，每臂约 1.25 万场`；`实验覆盖完整日夜，不反复偷看`。
- **需在 SVG 中体现的关键元素**：灰度滑杆 5%→10%；三态门禁灯（allow/hold/rollback）与阈值表；「回滚」红色闸门与「hold」黄色暂停键；Adoption 3% 的灰色样本表；1.25 万/臂的样本量标签；成功率高亮为 97.5% 的红色数字。

## Runtime 长老划重点（1 条）

> 指标口径先于结论：TTFF 算到首帧上屏，卡顿必须成对上报，分母和分桶不齐就不要下判断。

## 讲解页要点（对应正文小节）

1. **17.2 播放器生命周期与缓冲**：`AVPlayerItem` 状态迁移、缓冲观测、seek 代价；先把「起播/等待/播放/失败」的状态机画清楚，指标才有一致的采集点。
2. **17.5 质量指标公式**：TTFF、秒开率、卡顿率、单次卡顿时长、成功率、端到端延迟、切换次数、PSNR/VMAF 的定义与分母口径；未闭合卡顿要补到会话结束。
3. **17.6 发布门禁与灰度**：崩溃/启动一票否决；成功率跌破 98% 回滚；卡顿率、首帧 P90、Adoption 触发 hold；样本量与分桶纪律。
4. **17.7 症状 → 归因**：首帧慢、播放中卡顿、播放失败、音画不同步、延迟大、花屏、后台断播、清晰度反复跳的排查顺序，并与故障博物馆互链。
5. **17.3 / 17.4 播放能力边界**：HLS/DRM 与音画同步、后台播放、AirPlay 的观测点；不要把 `presentationSize` 变化直接当成码率切换。
